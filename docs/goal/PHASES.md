# Phases and exit gates

The overall goal remains active. Each phase ends in concrete evidence and a
bounded follow-up. Independent factory and laboratory tracks may advance in
parallel after the recovered baseline. No phase waives an original factory gate.

| Phase | Deliverable | Exit gate | State |
| --- | --- | --- | --- |
| P0 | Goal recovery and durable program | Every original and expanded objective mapped; actual repository/PR state inspected; continuation files and registered goal | Complete |
| P1 | Verified factory baseline and immediate quality repairs | Audit 21 existing servers' benchmarks, release/npm/Registry/provenance, canaries; run existing gate; close critical protocol gaps; record precise deficits | In progress |
| P2 | Executable CPU laboratory | Locked Python package; real ML, DL and RL training/evaluation; content-addressed datasets; immutable experiment records; reload and leakage tests; saved execution receipts | Locally validated; CI/review pending |
| P3 | Data and model lifecycle | Repeatable ingest/profile/split/lineage; model registry, inference, comparisons; model/dataset documentation and complete failed-run accounting | Planned |
| P4 | MCP laboratory pilot and factory release gates | Useful lab/data MCP tools; golden task suite; incumbent comparison; provenance/install/canary gates; first validated pilot releases | Read-only pilot validated; comparisons/releases pending |
| P5 | 100 maintained servers | 100 independently justified niches pass every station; verified releases, searchable discovery, CI/maintenance capacity measured | Planned |
| P6 | 500 maintained servers | Same evidence and gates; automated change impact, canary triage, adoption/issue metrics and measured maintenance capacity | Planned |
| P7 | 2,000 maintained servers | At least 2,000 qualifying distinct releases; sustainable upstream monitoring; per-server quality evidence and genuine task coverage | Planned |
| P8 | Complete training and research coverage | COVERAGE.md recipes, robust evaluation, foundation-model tuning, accelerator/distributed recipes, documented compute needs | Planned |
| P9 | Operational delivery and sustained outcomes | Model promotion/rollback/serving verified; real adoption and maintenance evidence; all requirement closures independently checked | Planned |

Immediate implementation slice: preserve continuity, produce a factual baseline,
fix the shared HTTP protection, and implement the CPU lab. Use free local compute
for bounded smoke workloads. Larger runs require an explicit resource plan rather
than an assumed unlimited GPU budget.

The scale milestones are quality-qualified counts, not deadlines. Grow from
verified cohorts. A cohort fails if correctness or maintenance deteriorates, even
when its package count increases.
